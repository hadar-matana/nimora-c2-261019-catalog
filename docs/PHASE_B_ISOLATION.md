# Phase B — isolation evidence and live checklist

## Local evidence

`pnpm --filter admin test:client` passes 15 groups. Fixture identities exist only as in-memory manifests, private temporary files and mocked provider calls: no simulated client cloud environment was created.

The tests exercise the existing Worker/OwnerAuth code with separate Map-backed Durable Object storage, real bcrypt cost 12, distinct owner credentials/version, host-only Secure HttpOnly SameSite=Lax cookies, cross-tenant stolen-cookie rejection, missing/foreign Origin, missing/wrong CSRF and disabled write gates before upstream calls. Actual CMS query, mutation and upload functions are bundled under mocked fetch and pinned to each server-side target; hostile body/query target parameters cannot redirect requests. Cross-project upload CDN responses are rejected. Streaming uses a local FixedLengthStream shim, not a live Workers memory-limit certification.

Manifest tests reject demo targets, incomplete branding, duplicate project/namespace/origin/backup identity, secrets/unknown fields and inconsistent publishing. Mock provider recovery records intent before creation, reconciles uncertain success once, rejects drift/tampered targets and refuses unknown existing resources. Backup fixtures cover integrity, original assets, encryption, tampering, no-overwrite recovery and isolated mock restore. Actual CLI dry-runs validate/render private configs and reject missing registries and live apply.

`verify-evidence` checks an operator's structured attestation against manifest/registry; it cannot prove that remote checks were performed. `credentialFingerprints` uses HMAC-SHA256 over actual secret values with the same private audit key across clients. Comparing salted bcrypt hashes does not detect password reuse. The four unique inputs are Sanity write token, owner password, credential version and backup key. Never commit either audit key or raw credentials. Retain fingerprints privately with evidence/account/revision timestamps; HMACs with unrelated audit keys are not comparable.

`hookObservation` requires observed records from both providers: exact client project/dataset and published filter, initially disabled Sanity hook, exact personal Cloudflare account/Pages project/client branch, identical private capability URL and native Cloudflare API webhook path. It emits HMAC fingerprints, not the hook URL. A Pages deploy hook URL normally starts with `https://api.cloudflare.com/client/v4/pages/webhooks/`, not the storefront hostname. A URL alone does not prove its owning project: GET both provider records. There is no live hook created in Phase B.

## Live checks required before any activation

Record request IDs, observed IDs/revision, time and reviewer for each result. Stop on missing evidence. Do not create additional clients merely to make the checklist green; authorize any restore target/test environment separately.

- [ ] Personal account and Sanity organization ownership/plan verified. Source checkout and deployed revision equal approved manifest SHA. Independent Sanity project with no shared dataset/project; exact public visibility approved.
- [ ] Unique Worker, new AUTH namespace ID/class/script binding; compare against full registry AND demo inventory. Sessions have no shared storage. Actual browser/HTTP cookie from one authorized client cannot authenticate on the other. Wrong owner/password/version rejected; session expiry/logout verified.
- [ ] New least-privilege server token per client, unique owner password/version/backup key; same-audit-key HMAC comparison covers all clients and known demo credential fingerprints without disclosing values. Validate provider roles/scopes; do not assume Free plan allows custom token roles.
- [ ] Anonymous API reads/writes rejected. Authenticated writes remain disabled initially; verify no upstream request occurs. Foreign/missing Origin and wrong/missing CSRF rejected. Host-only Secure HttpOnly SameSite cookie and exact TLS hostname observed in actual browser. Tests do not establish production browser DNS/TLS behavior.
- [ ] Actual reads, one separately authorized draft write, and one authorized disposable image upload reach only this client's Sanity project/dataset; inspect provider audit logs and returned asset URLs. Source/demo inventory remains unchanged. Do not grant writes solely to satisfy a test without authorization.
- [ ] Public admin/storefront/Studio bundles contain no real server credential/key/hook URL. Scan test sentinel values as well as known secret values privately. Inspect network requests for cross-project endpoints. Build variables alone do not prove the compiled output's target.
- [ ] Client Pages Git branch is exact; automatic production deployments and all branch previews disabled. Empty preview env is intentional. No wildcard preview can inherit a demo target. If previews are later enabled, require a dedicated approved client public target, no privileged token and a separate policy review.
- [ ] Private hook records match account/project/client branch and Sanity source/filter, disabled until explicit activation. One authorized publish triggers only that client's build; record build count/commit/URL, verify other clients and demo deployments/hooks unchanged.
- [ ] Native backup validated, separately copied encrypted archive and escrowed key recovered; live isolated restore checks source unchanged and semantic documents/originals intact. RPO/RTO recorded.
- [ ] Provider timeout/partial failure reconciled with inventory and journal; no unclaimed resource adoption or blind retry. No demo deployment script, secret copy or shared namespace used.

The final evidence JSON requires manifestHash, namespaceId, cmsProject, dataset, pages, origin, previewPolicy, four credential fingerprints, otherCredentials, and all checks listed by `verifyIsolationEvidence` (providerOwnership, namespaceBinding, noBrowserSecrets, sessionIsolation, originCsrf, readTarget, writeTarget, uploadTarget, backupRestore, revision, hookIsolation). If a hook exists include its redacted observation. `attestationValidated:true` still returns `writesEnabled:false`; activation is manual and separately approved.
