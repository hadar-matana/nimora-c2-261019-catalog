# Phase B — backup and recovery

Local fixtures passed; **no live export or import was performed**. Node 22+, Python 3 and the installed native Sanity CLI are required. The workflow covers Sanity content and its original uploaded image/file bytes, public client manifest, allowlisted resource metadata and recovery Worker configuration. Camera originals never uploaded to Sanity require separate private escrow.

## Capture and validate (later authorized read)

Use an assigned, verified namespace ID and a mode-0700, operator-owned canonical directory outside the repository. Symlink destinations are rejected. Files are mode 0600. Provision a unique 32-byte random encryption key through an approved secret manager; expose it privately as `CLIENT_BACKUP_KEY_BASE64`, and the scoped read token as `CLIENT_SANITY_READ_TOKEN`. Never type values into command arguments or store them in `.env`, manifests, logs or Git. Store key escrow separately from archives; test escrow recovery with a second authorized operator. The manifest's `backup.keyId` is a label, not the key.

```sh
pnpm --filter admin client-ops confirmation "$MANIFEST" backup-read
pnpm --filter admin client-ops backup-capture "$MANIFEST" "$EXACT_CONFIRMATION"
pnpm --filter admin client-ops backup-verify "$MANIFEST" "$ARCHIVE"
pnpm --filter admin client-ops retention-plan "$MANIFEST"
```

Capture independently queries raw document/asset inventory, runs native `sanity datasets export DATASET PRIVATE_PATH --project-id PROJECT --mode stream`, re-queries inventory and requires identical before/after snapshots. Quiesce edits first; any change stops capture. No `--no-assets`, `--no-drafts` or other content-disabling export flags. The validator checks actual native export structure and independently expected document IDs/revisions/full normalized content, counts, all asset IDs/source URLs/metadata, file sizes, SHA-1 originals and rewritten local asset references. It rejects cross-target assets/references, missing originals, duplicate or unsafe archive paths, symlinks/special files, secret-looking content, oversized entries and incomplete checksums. Native asset-reference rewriting is normalized to match the installed exporter; asset reference subfields stripped by that exporter cannot be recovered from its normalized representation. Native non-release `_.` internal system documents are excluded consistently with the exporter; drafts and release documents are included.

Each encrypted `.abk` contains exactly native-export.tar.gz, client-manifest.json, inventory.json, resource-metadata.json, worker-config.json and checksums.json. All files are checksummed with SHA-256; source asset hashes use Sanity's SHA-1 identity. AES-256-GCM authenticates the entire envelope, version marker, nonce and tag. Capture decrypts and fully validates the newly encrypted archive before finalizing its filename. Native export success alone is insufficient. Keys/tokens/passwords/hooks/DO session records are excluded; secret-like CMS fields stop validation rather than silently dropping content. Plaintext staging is removed in finally blocks on normal failure/success. Process crash, disk snapshots and SSD recovery can retain plaintext: use an encrypted filesystem, avoid untrusted shared hosts, inspect private orphan staging directories after crashes. No secure-erasure guarantee is claimed.

`backup-pack MANIFEST EXPORT INVENTORY METADATA` supports an independently prepared native export. The executable `Inventory` type in backup.ts requires full normalized nonasset documents and independent asset metadata, not just counts. Metadata must exactly match the eight allowlisted resource fields generated by capture. Arbitrary provider settings or credential dumps are rejected. Do not hand-invent inventory to make a bad export pass.

## Retention and offsite recovery

The configured retention window and keepLast (minimum two) produce a **plan only**, never deletion. Maintain at least two validated encrypted copies on independent private destinations, verify each copied archive with the escrowed key, restrict destination access and record copy hash/time/operator. Offsite transfer/storage automation and billing are not implemented. Only after a successful isolated restore and explicit pruning approval may an operator remove listed expired copies; never delete the newest keepLast or the only recoverable copy. Document retention obligations before real client data is accepted.

If the workstation/registry is lost, recover an encrypted archive and key separately. Create a new mode-0700 scratch directory and run:

```sh
pnpm --filter admin client-ops inspect-backup "$ARCHIVE" "$PRIVATE_SCRATCH"
```

This authenticates and validates the full bundle and returns its public manifest/resource configuration without accessing old paths or providers. It does not recover secrets or deploy anything. Reconcile actual provider inventory and intentionally choose new private backup paths; do not change the embedded manifest inside an existing archive. Recover source code from its exact recorded Git revision; rotate/recreate unique secrets privately, then rebuild. DO auth sessions are deliberately not restored; require fresh login. Worker recovery configuration starts disabled, with no public routes, and is not a full cloud-account backup.

## Isolated restore drill (later, explicit cloud-write authorization)

1. Verify source archive and independent key escrow. Record source inventory/count/hash. Never import into demo or original source project.
2. Separately authorize a disposable, separately owned Sanity **project**, not another dataset in the source project. Prepare an independently valid destination manifest/registry, credentials and empty dataset. Admin writes, publishing hooks and automatic builds remain disabled. Do not create this project during Phase B.
3. Observe destination emptiness with GET raw query, record `manifestHash, projectId, dataset, documentCount:0, observedAt` (within ten minutes), `writesDisabled:true, hooksDisabled:true`. Evidence is an operator attestation; re-read live immediately before import.
4. Request `confirmation DESTINATION isolated-restore`. Run the dry-run planner with source and destination:

```sh
pnpm --filter admin client-ops restore-plan "$SOURCE_MANIFEST" "$DEST_MANIFEST" "$OTHER_CLIENTS_REGISTRY" "$EXACT_CONFIRMATION" "$EMPTY_EVIDENCE"
pnpm --filter admin client-ops recover-local "$SOURCE_MANIFEST" "$ARCHIVE" "$PRIVATE_RECOVERY_DIRECTORY"
```

The registry excludes both source and destination. Local recovery exclusively creates native-export.tar.gz and refuses overwrite. It never imports. The planner returns native import argv pinned to the new project/dataset; it does not execute it.

5. Only after separate concrete import approval execute the returned `pnpm --filter studio exec sanity datasets import PRIVATE_EXPORT DEST_DATASET --project-id DEST_PROJECT`. Use destination Studio environment and private credentials. No replace/replace-assets, ignore-assets, allow-failing-assets or cross-dataset exceptions. Import errors leave writes/hooks disabled; inspect/reconcile rather than replacing content or retrying blindly.
6. Compare normalized documents, draft/published counts, IDs, original image bytes/metadata and all rewritten references against source inventory, allowing only documented destination project/asset-URL/ref transformations. Native import may change revisions/timestamps; compare semantic content and original hashes, not source revisions alone. Verify actual original downloads and a private/read-only storefront/admin render, auth/Origin/write gates, no external hooks. Confirm source inventory is unchanged.
7. Record RPO (last validated capture), measured RTO including key recovery/import/build/checks, counts, hashes, failures, costs and reviewer. Live native import compatibility, large datasets and offsite loss recovery remain unproven until this drill. Destruction of a disposable environment requires separate approval; no automatic cleanup.

Local tests use a tiny native-format fixture, draft, original PNG, adversarial archives, wrong keys, ciphertext tampering, full encrypted/local recovery and a mock import with reference rewriting. These establish local invariants, not a successful live Sanity restore.
