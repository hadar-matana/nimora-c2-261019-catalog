## Exact execution sequence

1. Authorize concrete accounts, resource names, source SHA, scope, per-provider budget and stop thresholds. Verify demo baseline first. Recheck current provider pricing/quotas/plan entitlement and disclose any necessary charge before creating anything.
2. Follow provisioning steps 1–6. Record each observed ID/confirmation in private journal; namespace initially unassigned, then reconcile real binding. Capture timer intervals and quota counters before/after each step. Ensure client previews remain disabled.
3. Create only client brand/About/options content. Upload client-owned originals in the existing admin within its current supported file-size/type limit; preserve originals offline. With 2MiB/photo planning ceiling, 300–500 uploads are at most roughly 600–1,000MiB before variants/metadata; this ceiling is a planning budget, not a new application upload limit. Check actual validation before preparing files. Log each upload byte count/hash and product image order, representative alt text, sizes/colors/prices and out-of-stock behavior. Keep data review separate from publication.
4. Enter ten products first; inspect product/draft/image/reference correctness. Pause on any cross-target request, wrong brand, missing image, privileged browser secret, unapproved build or quota/budget threshold. Then complete the remaining 90. Do not retry uncertain writes until querying for their actual result. Track unique IDs to avoid duplicate products/assets.
5. Reconcile exactly 100 intended product records and 300–500 intended original photo uploads, allowing documented reuse only if explicitly approved; separately count draft/published versions, asset docs, categories/options and About/settings. Spot-check all products and representative original downloads, desktop/mobile filters/detail/contact behavior, accessibility and admin error handling.
6. Quiesce writes; execute validated native backup and independent encrypted copy/escrow checks. Separately authorize an empty isolated restore project and import. Compare restored semantic content/assets; source/demo remain unchanged. Record RPO/RTO. Do not delete any environment automatically.
7. Complete live isolation checklist. Authorize one initial client storefront build, inspect result; authorize client-only publishing hook activation and one publish. Keep the demo production SHA fixed. Explicitly authorize writes only after evidence; count all build/retry activity.
8. Report measured human/system intervals, content/asset counts, bytes/storage/bandwidth, API/request/CPU/DO usage, builds/durations, failures/retries and actual provider invoice deltas. Actual charges may lag; mark pending, never zero without evidence. Leave environment cleanup/continuing service costs for separate approval.

## Budget and measurement rules

Potential marginal provider cost is **$0 only if** all activity fits verified available free entitlements and no paid plan/seat/domain is required. This is not a quote for the account. Cloudflare static Pages delivery is free under its documented static model; Worker/Functions/DO usage has separate limits. Sanity seats, projects, API traffic, original assets and image bandwidth depend on the actual project plan. Offsite backup provider/storage and any custom domain costs are unspecified. Paid Workers subscriptions and Sanity Growth seats must not be enabled as a workaround without explicit budget approval.

Current official references (reviewed 2026-10-19): [Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Sanity plans](https://www.sanity.io/pricing). Verify DO eligibility separately in the actual account; this task has not certified billing. Forecast formula: active_hours × agreed_hourly_rate + approved provider charges + approved domain/offsite cost. At an unspecified hourly rate R, labor forecast is 8.5R–18.0R; no currency/rate was supplied.
